## Clean-chain test (team request, factual answer below)

Team lead's own build info corrects an earlier note in this manifest: the site's "32-band parametric EQ" claim is correct per source (`MAX_BANDS = 32` in the Parametric EQ code) — it's the 10-band **Graphic** tab that `eq-curve.png` shows, not the Parametric one. See `eq-parametric.png` below for the actual 32-band-capable editor.

- `eq-parametric.png` — EQ Studio → **Parametric** tab (started from "Parametric: 10-Band Graphic EQ," which auto-mirrors the current Graphic tab's 10 bands as parametric Bell filters, then hand-edited into "Parametric: Custom"). Built by hand across 8 bands, deliberately varying filter type per band using the exact 7-type picker the team described (Bell, Low Shelf, High Shelf, Low Pass, High Pass, Notch, All Pass, all present and in that order): Band 1/31Hz = **Low Shelf**, Band 2/63Hz = **Bell** (small boost, left as-is), Band 3/125Hz = **Notch** (deep, narrow -12dB null, visibly different shape from a Bell cut), Band 5/500Hz = **High Shelf** boosted to +10.1dB (a real, visible rising plateau — 0dB shelves render flat, so I dragged the gain slider up to make the shape legible), Band 6/1kHz = **Low Pass** and Band 7/2kHz = **High Pass** together forming a visible band-pass wedge between them, Band 8/4kHz = **All Pass** (correctly renders perfectly flat at 0dB — All Pass affects phase, not magnitude, which the UI gets right). The screenshot captures the full curve plus the Band 5 editor panel open beneath it (type icon row, "500 Hz" frequency label), and the row of 8 band-frequency chips (31/63/125/250/500/1k/2k/4k) is in frame as the band-count tell — more bands (8k, 16k) exist off-screen to the right. This is a hand-built demo curve for the screenshot, not a factory preset.
- `player-clean-chain.png` — a file the team pushed to the device, `/sdcard/Music/BrandSongs/21 - Wagner - Tannhauser Overture CD master.flac` (same Tannhäuser recording, downsampled to 24-bit/44.1kHz — exactly the emulator's fixed output rate), showing as "Tannhäuser - Overture (CD master)" in the library without needing a manual rescan (it was already indexed, "AI Sonic Scan" counter had ticked up to 19 tracks). Captured with: Equalizer & Studio master switch OFF, True-peak limiter OFF (it auto-disables when the Equalizer master switch is off, since it's normally "Force-enabled by Equalizer"), Bit-perfect lock OFF, On-board output mode = Compatibility. Playing at 2:32 of 7:18. Footer chip reads `FLAC 24/44 → 32/44` — same sample rate in and out, only the bit depth changes (24-bit source to 32-bit float, which is the app's internal processing precision, set in Settings → Playback → Precision).
- `signal-clean.png` — the Signal Path sheet for that same clean-chain playback. **Direct factual answer to the team's question: the badge still reads "Resampled," not "Direct" or "Bit-perfect,"** even with a source that already matches the output rate and DSP fully bypassed. The chain shown is short and clean — FLAC i24/44.1kHz (green dot) → DSP "Bit-exact bypass" (green dot, confirming the EQ/limiter really are out of the path, no SRC stage or limiter stage listed at all) → On-board (AAudio) Shared (amber dot) → Internal output (AAudio SHARED) f32/44.1kHz (amber dot). The color change to amber happens exactly at the on-board/output stage, i.e. the "Resampled" verdict here is being driven by the 24-bit → 32-bit-float depth conversion and/or the fact that the output path is "AAudio SHARED" (the non-exclusive mixer path) rather than by any sample-rate math — there is no rate conversion happening (44.1kHz in, 44.1kHz out) and the badge still isn't "Direct." **Recommend treating this as confirmed: on this emulator, no combination of matching sample rate + DSP-off gets you a "Direct" badge — the badge is tied to the AAudio SHARED output path itself, which is the only path this virtual device can open at all (see the Bit-perfect-lock and Low-Latency-mode findings above). This is not a track-format problem; it's an emulator-audio-path ceiling.**

## Not captured / could not get, and why

- **AI Karaoke live screen** (Vocals/Original/Instrumental switch on Now Playing) — I did get the model-download flow itself working (see `extra-ai-enhancer-on.png` note) for the AI **Enhancer**, but the separate AI **Karaoke** model would not complete its own download in the time available: toggling it on triggers a "Karaoke model weights are not downloaded" error banner (with a Retry button) rather than a progress bar, and — importantly — turning the master "Karaoke" switch on in Settings → Playback _before_ its model is present leaves the app in a broken state where **all playback silently gets stuck at 0:00** (Play/Pause icon flips but the seek position never advances), even on freshly chosen tracks, until you either turn that switch back off or force-stop and relaunch the app. I did both to recover. So: the AI Enhancer path is now genuinely provable on this emulator (see below); the Karaoke path is not, and turning it on prematurely is actively harmful to the session — worth a bug note for the dev team independent of the marketing site.
- **A literal "32-band" graphic EQ** — the app's built-in Graphic EQ preset is fixed at **10 bands** (31Hz…16kHz), not 32. There is also a Parametric mode and an AutoEQ mode plus the semantic "Sculptor" and "Matrix" (radar) alternate EQ views, but none of those is a 32-slider graphic EQ either. **If the website copy claims "32 bands," flag this against the app — it does not match what's on screen in this build.**
- **`settings-about.png`** — no About/version screen exists anywhere in this app build (see note under Settings above).
- A few Quick-Play/Albums tiles (Satie, Mozart, one Haydn symphony) never finished generating real embedded-art thumbnails during the session and still show the generated concentric-circle placeholder — most other composers (Bach, Handel, Verdi, Wagner, Smetana, Saint-Saëns, Chopin, Dvořák, Grieg) did resolve to real portrait/painting art, and more kept resolving the longer the session ran (the refreshed `home.png` after an app restart has noticeably fewer placeholders than the first one did).

## Contradicts-a-marketing-claim notes

1. **Bit-perfect lock actively breaks playback on this emulator — it does not just "resample instead."** With Bit-perfect lock OFF (default), every track plays but gets resampled: `player-signal.png` shows the Signal Path badge as "Resampled," with the emulator's virtual audio output fixed at 44.1kHz/f32, so every high-res file (88.2/96/192kHz) goes through the SRC engine before reaching "AAudio SHARED" output. Turning Bit-perfect lock ON does not fix this and reveal a "Direct" path — instead **no audio plays at all** (`player-bitperfect.png`: stuck at 0:00, no format chip, Play never becomes Pause). I also tried the Output-settings route the team suggested (On-board output mode → "Low Latency," the app's own "bit-exact-adjacent" option) with the lock off — that alone also produces total silence; only "Compatibility" mode produces any sound on this virtual device. Conclusion: on this emulator there is exactly one working audio path, and it always resamples. The bit-perfect architecture is visibly real in the UI (the lock setting, a "Native Direct Output" status line, the live Signal-Path readout that would presumably show "Direct" on hardware that supports it) but a true bit-perfect pass-through could not be produced or screenshotted anywhere in this session, because `DAC Info` reports "Not connected" throughout (there's no way to attach a real or virtual USB DAC to this AVD) and the emulator's audio HAL apparently can't offer the exclusive/low-latency stream that both the lock and the low-latency mode require. **Recommend not using a "resampled" or "silent" screenshot as bit-perfect proof on the site; the claim needs either a real device capture or copy that doesn't imply it's demonstrable from any Android build.**
2. **"32-band EQ"** (if the site claims this) — not what ships; the graphic EQ is 10 bands. See above.
3. Initial playback blocker (session start, now resolved/understood): the very first track loaded before this session began ("Audio output unavailable — reconnect your DAC or check permissions") never recovered no matter what Output settings were changed — but every track started _fresh_ afterward played back correctly with real progress and a real Signal Path, for the whole rest of the session, _except_ for the two engine-breaking states documented above (Bit-perfect lock ON, and enabling Karaoke before its model downloads) — both of which are reproducible and both of which are fixed by toggling the setting back off (or, for Karaoke, sometimes a full app restart).
